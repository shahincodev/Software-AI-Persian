# Software-AI — سیستم خودکارسازی ویندوز با هوش مصنوعی

**نسخه**: 0.4.0 (عامل هوشمند با حلقه بینایی خودمختار)  
**پلتفرم**: ویندوز 10/11 — پایتون 3.11+  
**زبان‌ها**: فارسی (اصلی)، انگلیسی  
**مجوز**: اختصاصی (تمامی حقوق محفوظ است)

---

## نمای کلی پروژه

Software-AI یک **عامل هوشمند ویندوز** است که دستورات زبان طبیعی (فارسی/انگلیسی) را دریافت کرده و با **دسترسی کامل به سیستم** آن‌ها را اجرا می‌کند. برخلاف ابزارهای خودکارسازی سنتی، این سیستم هر درخواست را از طریق یک **حلقه عامل** پردازش می‌کند:

1. دریافت درخواست کاربر
2. ساخت زمینه سیستم (فایل‌ها، پوشه‌ها، درایوها، اقدامات اخیر)
3. تصمیم‌گیری هوش مصنوعی (فراخوانی ابزار یا پاسخ متنی)
4. اجرای اقدامات سیستمی
5. بازخورد به کاربر

### نسخه 0.5.0 — شناسایی هوشمند ارائه‌دهندگان API

- **شناسایی خودکار**: سیستم به‌صورت خودکار ارائه‌دهندگان API موجود در محیط را شناسایی می‌کند
- **فقط ارائه‌دهندگان فعال**: فقط از مدل‌های ارائه‌دهندگانی استفاده می‌شود که کلید API دارند
- **لاگ‌های شفاف**: نمایش ارائه‌دهندگان شناسایی شده در ابتدای برنامه
- **خطای بهتر**: بدون تلاش‌های غیرضروری برای ارائه‌دهندگان بدون کلید
- **گزارش وضعیت**: دسترسی به اطلاعات ارائه‌دهندگان از طریق `get_provider_info()`

### نسخه 0.4.0 — حلقه بینایی خودمختار

- **مشاهده صفحه**: عامل می‌تواند صفحه را ببیند و متن OCR و عناصر قابل مشاهده را دریافت کند
- **اعتبارسنجی بصری**: بررسی خودکار نتیجه اقدامات پس از اجرا
- **تلاش مجدد هوشمند**: در صورت شکست، با زمینه بصری تلاش مجدد انجام می‌شود
- **۱۸ ابزار استاندارد**: شامل ۵ ابزار بینایی جدید (screenshot, read_screen, find_element, verify_action, describe_screen)
- **دستور screen**: مشاهده دستی وضعیت صفحه از CLI

### نسخه 0.3.0 — فراخوانی ابزار ساختاریافته

- **فراخوانی ابزار یکپارچه**: ۱۳ ابزار استاندارد با اعتبارسنجی schema
- **اعتبارسنجی خودکار**: هر فراخوانی ابزار قبل از اجرا بررسی می‌شود
- **تلاش مجدد هوشمند**: در صورت خروج نامعتبر AI، حداکثر ۲ بار تلاش مجدد با زمینه خطا
- **مسیر اجرای واحد**: ابزارها از `action_factory` → `ActionController.execute_action()` عبور می‌کنند
- **فقط fallback اضطراری**: پارسر regex فقط وقتی استفاده می‌شود که AI کاملاً شکست بخورد

### نسخه 0.2.0 — تغییرات عمده قبلی

- **معماری عامل‌محور**: هر درخواست کاربر از طریق AI با دسترسی کامل به سیستم پردازش می‌شود
- **زمینه سیستم بلادرنگ**: هوش مصنوعی فایل‌ها، پوشه‌ها و درایوهای موجود را می‌بیند
- **بازخورد حلقه‌ای**: پس از هر اجرا، نتیجه به AI گزارش شده و خلاصه‌ای به کاربر نمایش داده می‌شود
- **CLI بازنویسی شده**: از 1038 خط به ~600 خط کاهش یافته، حذف مسیریابی دستی

### محدودیت‌ها (ارزیابی صادقانه)

- **اجرای کامل سرتاسری** از زبان طبیعی → تحلیل → برنامه‌ریزی → اجرا هنوز در حال اعتبارسنجی است. اجزا وجود دارند اما خط لوله به عنوان یک سیستم کامل آزمایش نشده است.
- **قابلیت اطمینان مدل هوش مصنوعی** به در دسترس بودن کلید API بستگی دارد. بدون کلیدهای معتبر برای Groq/Gemini/OpenRouter، سیستم به تطبیق کلمات کلیدی بازمی‌گردد که به میزان قابل توجهی توانایی کمتری دارد.
- **کیفیت OCR** به نصب Tesseract و وضوح صفحه بستگی دارد. متن ترکیبی (فارسی + انگلیسی) می‌تواند نتایج غیرقابل اعتمادی تولید کند.
- **اجرای مبتنی بر بینایی عامل مستقل** کند است (~۲-۵ ثانیه به ازای هر عکس صفحه + تحلیل LLM) و در رابط‌های کاربری پیچیده مستعد خطا است.
- **بدون خط لوله CI/CD** — تست‌ها باید دستی اجرا شوند.
- **فقط ویندوز** — پشتیبانی بین‌پلتفرمی برنامه‌ریزی نشده است.

## نمای کلی معماری

### معماری عامل‌محور (نسخه 0.4.0)

```
main.py (نقطه ورودی)
    ↓
SystemContext + VisionLoopManager — ساخت زمینه سیستم + مشاهده صفحه
    ↓
AIBrain.agent_chat() — AI با زمینه سیستم + وضعیت صفحه تصمیم می‌گیرد
    ├─ tool_call → اعتبارسنجی schema → تلاش مجدد در صورت خطا
    │   └─ action_factory → ActionController → اعتبارسنجی بصری
    │       └─ بازخورد → AI خلاصه می‌سازد → کاربر می‌بیند
    └─ chat_reply → پاسخ مستقیم به کاربر
```

### پشته پنج‌لایه (هسته اصلی)

```
لایه ۵ [UI]             main.py — نقطه ورودی مکالمه‌ای واحد
لایه ۴ [ORCHESTRATION]  IntentRouter → CapabilityManager
لایه ۳ [PLANNING]       IntentAnalyzer → PlanGenerator → PlanValidator → MemoryIntegrator
لایه ۲ [EXECUTION]      ActionController → ExecutionManager
لایه ۱ [CAPABILITIES]   DesktopVision, MouseControl, KeyboardControl, SmartWait,
                         BrowserCore, VoiceIO, SystemTools
```

### جریان اجرا

```
ورودی کاربر (متن/صدا)
    ↓
SystemContext.get_context() — ساخت زمینه سیستم
    ├─ فایل‌ها و پوشه‌های فعلی
    ├─ مکان‌های کلیدی ویندوز (Desktop, Downloads, Documents)
    ├─ درایوهای موجود (C:, D:, E:)
    └─ اقدامات اخیر
    ↓
AIBrain.agent_chat() — AI تصمیم می‌گیرد
    ├─ action: "tool_call"
    │   └─ ToolExecutor.execute()
    │       ├─ execute_command → اجرای دستور shell
    │       ├─ launch_app → باز کردن برنامه
    │       ├─ list_directory → نمایش محتوای پوشه
    │       ├─ read_file → خواندن محتوای فایل
    │       └─ ... (ابزارهای دیگر)
    │   ↓
    │   بازخورد اجرا → AI خلاصه می‌سازد → کاربر می‌بیند
    │
    └─ action: "chat_reply"
        └─ پاسخ مستقیم متنی به کاربر
```

### تصمیمات کلیدی طراحی

- **عامل‌محور**: هر درخواست از طریق AI با زمینه سیستم پردازش می‌شود، نه مسیریابی قاعده‌محور.
- **زمینه بلادرنگ**: AI قبل از تصمیم‌گیری، وضعیت فعلی سیستم (فایل‌ها، پوشه‌ها، درایوها) را می‌بیند.
- **ایجاد تنبلانه**: اجزای پرهزینه (DesktopVision, BrowserCore) فقط در اولین درخواست ساخته می‌شوند.
- **بازخورد حلقه‌ای**: پس از هر اجرا، نتیجه به AI گزارش شده و خلاصه‌ای به کاربر نمایش داده می‌شود.

```powershell
git clone https://github.com/shahincodev/Software-AI-Persian.git

# 2. ایجاد محیط مجازی
python -m venv .venv
.\.venv\Scripts\Activate.ps1

pip install -r requirements.txt

# 4. تنظیم کلیدهای API

python main.py
```

### حالت‌های امنیتی

- **safe** (پیش‌فرض): اقدامات پرخطر نیاز به تأیید صریح `y/n` دارند. آستانه در ۷۰.
- **power**: اعلان‌های رضایت کمتر، تحمل بیشتر برای اقدامات خودکار.

## محدودیت‌های فعلی

۱. **وابستگی به کلید API**: بدون کلیدهای API معتبر، سیستم نمی‌تواند از هوش مصنوعی استفاده کند.
۲. **فقط ویندوز**: متکی به Windows API (pywin32) برای مدیریت پنجره است.
۳. **بدون CI/CD**: تست‌ها باید دستی اجرا شوند.
۴. **کیفیت OCR**: به نصب Tesseract و وضوح صفحه بستگی دارد.
۵. **خودکارسازی مرورگر**: یکپارچه‌سازی Playwright هنوز کاملاً در مسیریابی ادغام نشده.

## نقشه راه (مرتب)

۱. **✅ Phase 1 — تثبیت خط لوله اجرا**: اعتبارسنجی مسیر Intent → Router → ActionController → Execution.
۲. **✅ Phase 2 — فراخوانی ابزار ساختاریافته**: جایگزینی پاسخ‌های چت با فراخوانی ابزار معتبر با schema.
۳. **✅ Phase 3 — حلقه بینایی خودمختار**: یکپارچه‌سازی DesktopVision، اعتبارسنجی بصری، تلاش مجدد.
۴. **Phase 4 — برنامه‌ریزی چندمرحله‌ای هوشمند**: پشتیبانی از درخواست‌های پیچیده چندعملی.
۵. **Phase 5 — حافظه پایدار**: یادآوری مکالمات قبلی، یادگیری ترجیحات کاربر، حافظه کوتاه‌مدت و بلندمدت.
۶. **Phase 6 — مدیریت نشست‌های چت**: ایجاد، حذف، جستجو و سوئیچ بین نشست‌های مکالمه.
۷. **Phase 7 — درک محیط ویندوز**: تشخیص خودکار برنامه‌ها، مسیرها، پوشه‌های محلی‌شده.
