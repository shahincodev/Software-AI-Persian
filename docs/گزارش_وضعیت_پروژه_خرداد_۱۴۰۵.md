## ۲. معرفی پروژه

**نام کامل:** Software-AI (سیستم خودکارسازی هوشمند ویندوز با هوش مصنوعی)  
**زبان:** فارسی / انگلیسی (دو زبانه)  
**ورژن:** 0.1.0  
**پدیدآورنده:** Shahin (shahincodev)

پروژه از یک معماری **Capability-Driven** (هدایت‌شده با قابلیت) پیروی می‌کند که جایگزین معماری قدیمی mode-based شده است. کاربر از طریق یک رابط CLI مکالمه‌ای (چت) با سیستم ارتباط برقرار می‌کند و سیستم به صورت هوشمند تشخیص می‌دهد که کدام قابلیت‌ها باید فعال شوند.

**نقطه ورود:** `python main.py`

## ۴. معماری سیستم

### لایه‌های معماری (۵ لایه)

```
لایه ۵ [واسط کاربر]       main.py — رابط خط فرمان مکالمه‌ای
لایه ۴ [ Orchestration ]  IntentRouter → CapabilityManager
لایه ۳ [ Planning ]       IntentAnalyzer → PlanGenerator → PlanValidator → MemoryIntegrator
لایه ۲ [ Execution ]      ActionController → ExecutionManager
لایه ۱ [ Capabilities ]   DesktopVision, MouseControl, KeyboardControl, SmartWait,
                           BrowserCore, VoiceIO, SystemTools
```

### جریان اجرا

```
ورودی کاربر → IntentRouter.route()
  ├─ IntentAnalyzer.analyze()    (تحلیل درخواست)
  ├─ CapabilityManager.activate() (فعال‌سازی تنبل قابلیت‌ها)
  ├─ SafetyConsentManager        (ارزیابی ریسک و اخذ رضایت)
  └─ RouteType dispatch (۷ مسیر)
       ├─ CHAT_RESPONSE     → AIBrain.ask()
       ├─ BROWSER_USE       → BrowserCore
       ├─ DESKTOP_AUTOMATION → ActionController
       ├─ AUTONOMOUS_AGENT  → AutonomousAgent
       ├─ TASK_MODE         → TaskEngine
       ├─ CLARIFICATION_NEEDED → درخواست توضیح
       └─ fallback          → ActionController.process_request()
MemoryIntegrator.record_execution()  (ثبت در حافظه)
```

### تصمیمات معماری کلیدی (ADRs)

1. **کنار گذاشتن معماری mode-based** → تشخیص خودکار قابلیت
2. **مقداردهی تنبل (Lazy initialization)** با ثبت factory در CapabilityManager
3. **ادغام به جای ایجاد** — ۴ ماژول ادغام شدند (dialog_manager, memory_system, master_controller, intelligent_agent)
4. **Wrapperهای سازگار با عقب** با DeprecationWarning
5. **اجرای یکپارچه** در ActionController (شامل دسکتاپ و سیستم)
6. **یک فایل SQLite واحد** با دو سیستم schema (بدهی فنی)

## ۱۱. قوانین و اصول پروژه

بر اساس **`AI_PROJECT_RULES.md`**، پروژه از ۱۵ اصل مهندسی پیروی می‌کند:

### اصول کلیدی
1. **Capability-Driven** — معماری مبتنی بر قابلیت (جایگزین mode-based)
2. **Refactor Over Rewrite** — بازنویسی نکن، بازآرایی کن
3. **Consolidation Over Creation** — ادغام در ماژول‌های موجود، نه ایجاد ماژول جدید
4. **Parser Never Executes** — تحلیل‌گر هرگز اجرا نمی‌کند
5. **Executor Never Parses** — اجراگر هرگز تحلیل نمی‌کند
6. **Backward Compatibility** — حفظ سازگاری با عقب با DeprecationWarning
7. **Persistent Memory** — حافظه SQLite برای یادگیری از تاریخچه
8. **Safety First** — همیشه فیلتر امنیتی قبل از اجرا

### اصول کدنویسی
- **فاصله ۴ فضایی**، snake_case برای توابع، PascalCase برای کلاس‌ها
- **Async-first** برای ارکستراسیون، **Sync** برای قابلیت‌های سطح پایین
- **Dataclass-heavy** برای ساختارهای داده
- **مستندات دو زبانه** (docstring فارسی، API انگلیسی)
- **Exception handling گسترده** با `logger.exception()` (بدون سلسله‌مراتب exception سفارشی)

## ۱۴. نتیجه‌گیری

پروژه **Software-AI** در وضعیت **توسعه فعال** قرار دارد و پیشرفت قابل توجهی در بازآرایی معماری از mode-based به capability-driven داشته است. نقاط قوت و ضعف پروژه به شرح زیر است:

### نقاط قوت ✅
- معماری تمیز و مقیاس‌پذیر capability-driven
- پشتیبانی گسترده از قابلیت‌های مختلف (کنترل دسکتاپ، بینایی، صوت، مرورگر)
- مستندات جامع و دو زبانه (فارسی/انگلیسی)
- سیستم امنیتی چندلایه (فیلتر، رضایت، ارزیابی ریسک)
- پشتیبانی از چندین provider هوش مصنوعی

- نبود CI/CD
- بدهی فنی در دیتابیس (دو schema)
